# CLAUDE.md

Guidance for Claude Code (claude.ai/code) when working in this repository.

## Overview

Slaw is an **agentic desktop workspace for working with data where it already lives** — DataGrip/DBeaver-shaped, with an AI agent, live notebooks, skills and A2UI artifacts, all exposed to external agents over MCP.

- **Connections** keep the data where it is (local DuckDB, MotherDuck, Postgres, MySQL, SQLite, S3/GCS/R2, Azure, DuckLake, Iceberg/Delta). They are attached on first use into one in-memory **DuckDB hub** per workspace.
- A **workspace** is a folder (optionally a git repo): `slaw.yaml`, `notebooks/*.slnb`, `queries/*.sql`, `skills/<name>/SKILL.md`, `artifacts/<name>/` (data artifacts), `semantics/{entities,metrics,joins}/*.yaml` and `semantics/glossary.md` (the semantic layer, `docs/reference/semantics.md`), `watches/<name>.yaml` (standing questions with a condition, checked on demand, `docs/reference/watches.md`), `data/`. Machine-local state lives in `.slaw-local/` (git-ignored).
- **Credentials** live in the OS keychain or env vars, never in the folder.
- **`.slaw`** is an exchange **bundle** (zip, optional age passphrase) of notebooks, queries, skills, data artifacts, semantic definitions, watches and connection definitions. It never holds data or credentials. Older data-holding SQLCipher `.vibe` files are not opened (vibe-app#110 was dropped).

**Read first:** `docs/direction.md` (north star; §9 "As delivered" lists what changed from the plan in vibe-app#105; the earlier Access-parity and page-system removals are recorded in `docs/archive/` and git history) and `docs/README.md` (index of every doc). Shipped surface reference: `docs/reference/`. Next direction: `docs/plans/answers-you-can-check.md` (umbrella #250, epics #241-#249; receipts, verifier, semantic layer). Closed epics: vibe-app#105, #162; cleanup survey: vibe-app#137 (`docs/reviews/cleanup-2026-10/`).

## Tech stack

- **Go 1.27+**, `CGO_ENABLED=1` (DuckDB bindings). Cobra + Viper for the CLI and config.
- **Engine:** `duckdb-go` (`github.com/duckdb/duckdb-go/v2`, embedded DuckDB 1.5) is the single query/CRUD engine. There is no SQLite or SQLCipher dependency (removed in vibe-app#137): tests use DuckDB, FileStores in `t.TempDir()`, or the store `Mock`s.
- **Desktop GUI:** Wails v2 + **Vue 3** (`studio/`). UI uses SchoolHouse (`studio/frontend/src/schoolhouse/`), themed through `--slaw-*` semantic roles (`docs/reference/themes.md`). Editor is CodeMirror. A2UI charts are hand-drawn CSS/SVG.
- **Agent:** `internal/llm` on `charmbracelet/fantasy` (providers: `docs/reference/llm-config.md`); tools, sandbox and approvals in `internal/agents`; MCP in `internal/mcp` and `internal/hub` (`docs/reference/mcp.md`).
- **TUI:** BubbleTea + Lipgloss (`slaw studio` without `--gui`): SQL REPL, read-only table browser, notebook list.
- **Logging:** `log/slog`. **Tests:** `testing` + testify.

## Build commands

Automation is **Taskfile.yml**, not a Makefile.

```bash
task              # default: lint + test + build
task build        # build the slaw binary (./cmd/slaw; also `go install github.com/SandwichLabs/slaw/cmd/slaw@latest`)
task test         # Go + Vitest tests (alias: task t); task test:frontend is Vitest only
task lint         # golangci-lint (task lint:fix to auto-fix)
task typecheck    # vue-tsc over studio/frontend (`npm run typecheck`); part of `task lint`, blocking in CI, 0 errors
task studio:dev   # Wails dev server (NOT bare `wails dev`: needs -tags webkit2_41,duckdb_arrow)
task build:studio # Studio desktop app (build:studio:linux on Linux); stamps the version, then restores wails.json
scripts/gen-icons.sh  # regenerate appicon.png + Linux icons from studio/build/icon/slaw.svg
go test -v ./internal/workspace/   # one package
ast-grep scan -c tools/ast-grep/sgconfig.yml cmd internal studio  # architecture rules (CI-blocking at error severity), incl. ts-window-go-outside-binding-layer
```

**Release**: `task release` prints the procedure; a release is just pushing a `v*` tag (`-rc`/`-test` tags are prereleases; every release is a draft until a human publishes it). See `docs/packaging.md`, "v0.1.0 unsigned pipeline, as built".

**CI** (`.github/workflows/ci.yml`): every PR runs the Linux `test` job (vet, `xvfb-run go test`, golangci-lint, vitest, frontend build, shellcheck) and a Linux amd64/arm64 build smoke on ubuntu-22.04 (CLI round trip + `wails build`). macOS runs only on push to main and `workflow_dispatch` (10x minutes). vue-tsc (`npm run typecheck`) and govulncheck (#41) are blocking, and build-smoke also checks `AppApi` arities against the regenerated bindings (`check-arity.mjs`). A govulncheck finding means bumping the module or the Go patch release (go.mod's `go` line is the toolchain CI and release use, now 1.27.3). Actions are pinned to commit SHAs; the golangci-lint version is pinned in the workflow, so bump it with the local one.

Keep the Wails CLI at the `github.com/wailsapp/wails/v2` version in go.mod (v2.17.1; CI and release pin it as `WAILS_VERSION`, and a CLI older than go.mod makes `wails dev`/`wails build` rewrite go.mod, #270). Wails v2.16 and later load Go 1.27, so the old `WAILS_GOTOOLCHAIN` pin (vibe-app#92) is gone.

CLI: `slaw workspace init`, `query` (`-e` edits in $EDITOR), `lsp` (`lsp snapshot`), `import`, `export`, `conn`, `artifact` (`artifact list`, mirrors the Library's artifact kinds; `artifact view` allows or denies a view; `artifact render` draws an allowed static `view: html` page to files), `config` (`config llm` mirrors Settings → App's provider picker; keys stay on `config llm-key`; `config updates` mirrors the About > Updates toggle), `update` (check, then install after confirmation), `semantics` (`list`, `show`, `proposals`, `show-proposal`, `accept` (`--all [--kind] [--yes]` for bulk), `reject`, `check`, `profile`), `receipts` (`show <id> [--json]` prints one receipt as the Evidence drawer's sections, `list [--surface S] [--limit N] [--json]` the newest first (R4a); `settings [--keep-params on|off] [--days N] [--max-count N] [--max-mb N]` shows or sets this person's retention, `clear [--yes]` deletes every receipt; R4b), `watch` (`list`, `show`, `check`, `history`; `check` exits 0 all ok, 1 an alert fired, 2 an error and none fired), `repl` (the Studio Console tab on a terminal; people only, needs a TTY), `studio` (`--gui` for desktop), `mcp serve`. `init` aliases `workspace init`. Old container commands (`info`, `verify`, `compact`, `rekey`, `dump`, `passphrase`) are hidden stubs that point to `slaw workspace init`.

## Key concepts

**Workspace and files.** Files are the source of truth; writes are compare-and-write and a watcher picks up outside changes (git, editors, other processes). Notebook outputs are never persisted. A committed `slaw.yaml` can only *tighten* the agent's limits; looser per-person settings live outside the folder. A workspace `.env` is loaded only after the person allows it (direnv-style: allow is keyed by path + content hash, deny by path; decisions in the user config dir), into a per-workspace overlay read by `env:` sign-ins, never `os.Setenv`.

**Connections.** Read-only by default, connect on first use, with a visible status. The connection name is the catalog alias in SQL (`prod_pg.public.orders`). Metadata-driven formats (DuckLake, Iceberg tables and catalogs (`iceberg_catalog`), Delta) may be defined in any scope, a committed `slaw.yaml` and a `.slaw` bundle included: the tool runs what DuckDB itself runs and warns where a shared definition is shown or imported (`workspace.MetadataWarning`, "table metadata decides which files DuckDB reads"); credential rules are unchanged. MotherDuck cannot be attached read-only.

**Run receipts (E1, `docs/plans/run-receipts.md`).** A receipt is a small machine-local record that a question was asked and what it touched, kept in `.slaw-local/receipts/` (never bundled, pruned by a per-person policy). It is not an output: it holds no row values (the result is only an HMAC fingerprint) and no credential, and text that `engine.Recordable` refuses is kept as a hash only. "Notebook outputs are never persisted" still holds for the folder. Every read mints one: the person's editor, CLI and console (after `.receipts on`, per session), the render-time reads (A2UI, notebook cells, artifacts, a metric's Try it, assertions, watches) and the agent's `run_query`/`run_saved_query`/`preview_query` (which return a `receipt_id` to cite); a write, the policy's classification, catalog listing and the save-time vet mint none, and a store that cannot be written never fails a run. How long they are kept is this person's own setting (R4b, `docs/reference/receipts.md`): `workspace.SetLocalReceipts` writes `LocalConfig.Receipts` in the config directory (never `slaw.yaml`, never a bundle; an untrusted local file means the defaults), `ReceiptPolicy` clamps it when the recorder opens, Studio's `GetReceiptSettings`/`SetReceiptSettings`/`ClearReceipts` (`studio/receipts.go`) and `slaw receipts settings|clear` are the two surfaces. Reading one is R4a (Settings > Workspace > Receipts also lists the newest ten, each opening the drawer by id): `receipts.Store.List` (newest first, filtered by surface, bounded) and `Summary` behind `slaw receipts list`/`ListReceipts`, `GetReceipt`/`slaw receipts show` behind the Evidence drawer, `receipts.NoteFor` (a reason class, `not_kept` or `unavailable`, on `QueryResult`/`A2UIQueryResult` as `receipt_note` when a run that should have a receipt has none), and `RunA2UIQueryIn`'s `RenderSource` so a render-time read gets the `notebook_cell` or `a2ui` surface and a ref (`notebooks/<id>.slnb#<cell>[/<component>]`). R5 is the agent's access and the chat: `get_receipt` (introspect, every tier, `agents/receipts.go`) returns a receipt only when it is the agent's and its `agent_session` equals the session on the context (an MCP SSE session, one per stdio process, a Studio chat conversation, the AI cell dialog), else the same "no receipt with that id" as a missing one, and never the session; Go mints the chat conversation id (`chatTurns.conversation`, the newest 32 ids issued per open workspace, any other starts a new one); and the chat's chips and number marks come from the turn's in-memory reads (`studio/agent_runs.go`, `internal/llm/numbermatch.go`: the exact rules are in `docs/reference/receipts.md`; the grounding check is unchanged).

**Notebooks (vibe-app#66).** JSON documents of `sql` / `markdown` / `a2ui` cells (schemaVersion 2; a cell may name a `connection`). Every data cell re-runs on open. The agent authors cells in **task mode**: `preview_query` before a terminal `write_cell` or `need_more_info`.

**Skills (vibe-app#62).** `SKILL.md` documents (`name`, `description` + markdown). The prompt advertises name and description; the agent fetches bodies with `read_skill`. Built-ins are embedded. Table-bound skills load only when the table has rows.

**Data artifacts (#162, plan `docs/plans/data-artifacts.md`).** A parameterised, live view stored as files: `artifacts/<name>/artifact.yaml` (typed parameters with defaults and *named* queries) plus `view.a2ui.json`. It stores questions, never answers. `artifacts.Bind` turns (query name, raw values) into the manifest's SQL text unchanged plus bound params; a value never becomes SQL text. The store refuses rather than repairs (strict YAML, byte caps before decode, no anchors/aliases), and one `Rev` covers both files. The SQL policy runs in `internal/agents` at save and again at every run, in every tier, so a hand-edited, git-pulled or bundled artifact is held to it too. No tool runs an artifact for the agent (Studio runs it for the person). Level 2 is the **script view** (`view: script`, `view.js`): it shows as source until the person allows it (path + `ViewHash`, decisions in `views.json` via `internal/trustfile`; the agent can never allow), then runs in a terminable Web Worker served by `studio/viewserver.go` under a per-grant token with a deny-all CSP, gets rows only through `RunArtifactViewQuery`, and returns an SVG (shown as an inert `<img>`) or an A2UI page Go validates. A static **HTML page** (`view: html`, `html/` templates, P3) is allowed the same way (`PageHash`), rendered in Go (`artifacts.RenderHTMLPage`, bounded by a work budget, an output cap and a deadline, queries only through `RunArtifactQuery`) and shown in a `sandbox=""` frame from `/slaw-view/<token>/page` under a per-artifact token and a script-less CSP, with Studio's page narrowed to `frame-src <origin>/slaw-view/` (emitted at build time); scripted pages and capabilities are below (`docs/plans/html-artifacts.md`).

**Custom artifact views (`view: script`, #159).** An artifact may name `view.js` instead of `view.a2ui.json`; the code is someone else's or the agent's, so it shows as source and runs nothing until the person allows it. Allow is keyed by the folder's canonical path plus `artifacts.ViewHash` (version-tagged, length-prefixed over `artifact.yaml` and the view files), kept in `views.json` beside `dotenv.json` (`internal/trustfile`), and refused if the files changed since they were shown. No agent tool or MCP method can allow, deny or revoke. The worker that runs an allowed view is step 9.

**Scripted HTML pages (`view: html` with script, #162 step P4).** An allowed scripted page opens only from Studio, in a native window owned by a helper process (`slaw-studio --view-host`, the same binary; `internal/pagehost` is the pipe protocol). The helper gets no workspace, credential or store: Studio renders the page, sends its hashed files over two pipes, pins the artifact by name, and answers `slaw.run` through the same gates as every artifact query. Linux starts it only inside bubblewrap (no network, an allow-listed filesystem view, a tree kill); macOS uses CSP, a navigation policy, a content rule list and a dead proxy, with one accepted, disclosed leak (#189). If the gate cannot be built there is no window. A page gets only the capabilities its manifest declares (`state` local only, `download` through the native save dialog behind the helper's own record of a physical input, and a dialog throttle, `ask` as one tool-less completion behind its own toggle), each a Studio method behind the pipe, never an agent tool. **The allow prompt (P6)** lists the files, the queries with their connections, each declared capability in plain words (`ask` names the configured provider), the macOS network disclosure and a never-ask-for-a-credential line (carried in `ArtifactViewState`, text in `artifacts/pageprompt.go` shared with `slaw artifact view status`); Settings > Workspace > Pages lists decisions, the per-page `ask` toggle and the recent model use. `write_artifact` takes `html_files` (text only) and `get_artifact` returns them; no tool renders, runs or allows a page, and every agent edit changes the hash. A bundle carries a page as `artifacts/<name>/html/<path>` entries, vetted before any write, and never a decision. Details: `docs/reference/artifacts.md`.

**A2UI artifacts (vibe-app#67).** `{ title, components[] }`, twenty component types (the original thirteen plus the KINETIC charts `areaChart`, `columnChart`, `ringChart`, `radarChart`, `sankeyChart`, `heatmap`, `streamChart`), closed color enum, unknown fields rejected. `stat` / `table` / every chart take inline data or a live `sql` binding; every chart takes a closed `motion` object (easing preset, speed, stagger, spring tuning), animated in `a2ui/useMotion.ts` and off under reduced motion.

**Agent policy.** One tool registry, consumed by the in-app runner and by MCP. Sandbox tiers `read-only`, `read-write`, `full`. A write needs all three: the tier allows it, the connection is writable, and the person approves (always asked for non-local connections; headless MCP refuses them). SQL is an allow-list parsed before `EXPLAIN` binds it (`docs/reference/agent-policy.md`). Guardrails (vibe-app#70): grounding check, empty-result explanation, tool-result budget.

## Conventions

- **`internal/` not `pkg/`**; Cobra + Viper; `log/slog` passed by dependency injection; services created in `cmd/slaw/main.go`/`cmd/` and passed down, no globals.
- **Complexity is linted**: `gocognit` (min 30) runs in `golangci-lint`; only the named waivers in `.golangci.yml` (tokenizers, wire-format decoders) may exceed it. Split a long function into named steps instead of adding a waiver.
- **Wrap errors** with context: `fmt.Errorf("failed to open workspace: %w", err)`.
- **Interfaces for testability**; a `mock.go` only when a test needs it. Co-located tests with testify. Functional options for complex constructors.
- **One tool surface**: new agent capabilities are `ToolDef`s in `internal/agents`, never bespoke `fantasy` tools in `internal/llm`.
- **Model output never reaches a style attribute**: A2UI colors are a closed enum; validators reject unknown fields.
- **No hex in stylesheets**: use `--slaw-*` roles (or bridged `--sh-*`); translucent variants via `color-mix()`. Themes are validated by `theme/schema.ts` and must pass the AA contrast spec.
- **Thin views**: a `.vue` file is at most 600 lines and 150 script lines. A view wires composables (`composables/use*.ts`, one per job: `useNotebookSave`, `useTableCrud`, …) and renders; the conflict banner flow is `useConflict`, popup-menu keys `useMenuKeys`, the A2UI live `sql` binding `a2ui/useLiveQuery`. `studio/frontend/scripts/check-vue-size.mjs` enforces it in CI.
- **Focus is visible**: `theme/bridge.css` owns the `:focus-visible` ring; never `outline: none` without it. Ad-hoc modals use `composables/useModal.ts`.
- **QA in a real browser**: Rodney against the Wails-bound dev server at `:34115` (see `docs/contributing/rodney.md`); Vitest specs are supplementary, never the acceptance criterion. The older Rodney verification protocol is in `docs/archive/parity-remediation-plan.md` §1.
- **Docs move with code**: keep `docs/reference/` and the architecture tree above current; `internal/docsref` fails when they drift.
- **Releases** are `.github/workflows/release.yml`: push a `v*` tag and it builds natively on four runners, stamps the version with ldflags, and creates a draft release. No GoReleaser.

## Design principles

- **Trust rules:** never store a credential in a config file, a `.slaw` bundle, a log line, an error shown to the UI or agent, or anything the agent can read. Credentials are write-only across the Wails bridge and MCP.
- **Data stays where it lives**: Slaw reaches data in its connections; it doesn't copy it into its own format.
- **The workspace is the app**: a folder of plain, diff-friendly files you can version, review and share via git.
- **Read-only until asked**: agent writes need the tier, a writable connection, and approval.
- **Single-user first**: sharing is via shared backends and git; multi-user mesh is deferred.
- **One tool surface**: the built-in agent and MCP clients see the same tools with the same gating.
- **AI as collaborator, not dependency**: everything works without AI.
- **Live, not frozen**: notebooks and artifacts store questions (SQL), not answers.
- **Progressive disclosure**: skills advertise a line and load on demand; connections connect on first use.
